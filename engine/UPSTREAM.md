## Local changes

- Removed `utils/LogSender.java` (network log upload); `BlackBoxCore.sendLogs(...)` overloads are now no-ops that call `listener.onFailure("Log upload is disabled")` if a listener is given; `ClientConfiguration.getLogSenderChatId()` returns null.
- Removed `BlackBoxCore.startLogcat()` and its call, plus the helpers only it/`sendLogs` used (`logDeviceInfo`, `getDeviceInfoString`).
- Removed `closecode/Entry.java`; `BlackBoxCore.closeCodeInit()` is an empty no-op.
- `utils/SimpleCrashFix` no longer installs a global uncaught-exception handler (no swallowed crashes, no `sendLogs`); it only installs the context wrapper hook.
- `BPackageManagerService.installPackageAsUserLocked` returns a failed `InstallResult` (with the exception message) when a Throwable is caught.
- `BLocation(Parcel)` reads speed, bearing, accuracy in the same order they are written.
- `ILocationManagerProxy` `getLastLocation`/`getLastKnownLocation` null-check the fake location and fall through to the real call when none is set.
- `BLocationManagerService`: `addTask` sleeps when location is null and exits when the listener is removed; listener map is a `ConcurrentHashMap`.
- Added `isPackageRunning(String, int)` to `IBActivityManagerService` (AIDL), `BActivityManagerService`, `BActivityManager` and `BlackBoxCore`; static `isRunningApplication` now delegates to it.
- `DaemonService`: removed `DaemonInnerService` (it cancelled the foreground notification) and its manifest entry; notification title/text come from Bcore string resources (`daemon_notification_title`, `daemon_notification_text`: "Clone engine running").
- Manifest: added `PROPERTY_SPECIAL_USE_FGS_SUBTYPE` property to the `DaemonService` `<service>`.
- `Bcore/build.gradle`: replaced `tasks.matching { ... }.all` with `tasks.configureEach` for the AIDL-comment-stripping hook; the eager `matching` realised the R8 task before AGP registered its build service and broke configuration ("R8D8ThreadPoolBuildService is not registered").
- Per-clone device profile: added `entity/device/BDeviceProfile`, `fake/frameworks/BDeviceManager` (one JSON file per (userId, package) at `<system dir>/device-profiles/<userId>/<package>.json`, atomic write; helper `BEnvironment.getDeviceProfileFile`) and `core/device/DeviceProfileApplier`.
- `BActivityThread.handleBindApplication` loads the profile right after `NativeCore.init` and applies it: reflective `android.os.Build` fields plus native property overrides via new JNI `NativeCore.setSpoofProps(String[], String[])` (registered in `BoxCore.cpp` `gMethods`).
- `cpp/Utils/VirtualSpoof.cpp`: removed the hard-coded global "Pixel 6" property table (it also applied to the host); the table is now empty by default and set per process (copy-on-write, mutex-guarded snapshot). Only `__system_property_get` is hooked; `__system_property_find`/`__system_property_read_callback` readers are not.
- `ITelephonyManagerProxy` (getDeviceId, getImeiForSlot, getMeidForSlot, getDeviceIdWithFeature), `IDeviceIdentifiersPolicyProxy` (serial) and `IWifiManagerProxy` (getConnectionInfo MAC) return the profile value when set, else the previous behaviour.
- ANDROID_ID: `SystemProviderStub` and `ContentProviderStub` pass `call` results through `DeviceProfileApplier.patchSettingsCall`, which substitutes the `value` of a `GET_secure`/`android_id` settings call with `profile.androidId`. `AndroidIdProxy`/`DeviceIdProxy` are left in place (inert: `getWho()` is null).
- Added `BlackBoxCore.isEngineAlive()`: true only when `getService(PACKAGE_MANAGER)` returns a binder that is alive and answers `pingBinder()` (`waitForServicesAvailable`/`isServicesAvailable` are set true on every path, including fallbacks without a server).
- `IActivityManagerProxy` `bindIsolatedService`/`bindServiceInstance`: the isolated-service instance name is no longer erased for binds that pass through to the real system (WebView sandboxed renderer); it is made unique per process (`<name>_<pid>`). It is dropped only when the bind is redirected to a host stub service. Erasing it made every clone process bind the same renderer instance ("Service is already bound by pid ..."), leaving WebViews blank in all but the first process.
- `BProcessManagerService`: death cleanup (`onProcessDie`, `killAllByPackageName`) used `ProcessRecord.buid` (app id only) as the process-map key, which addresses user 0's entry for every user. A dying process of user N removed user 0's record and left its own dead record behind, whose slot could then be reused by another clone, cross-wiring providers between clones. Cleanup now uses the user-qualified key, removes only the matching record, and `startProcessLocked` never returns a record whose binder is dead.
- `BActivityThread.initProcess` rejects re-initialising a live process for a different user id.
- `InnerReceiverDelegate`: a broadcast sent by a clone is delivered to dynamically registered receivers only inside the sender's virtual user (ordered broadcasts are finished when skipped).
- `BActivityThread`: a process is given (and installs) only the providers declared for it, or marked multiprocess, as on real Android. Previously every process received the package's full provider list; packed apps install whatever is in `AppBindData.providers`, so secondary processes got private, empty copies of main-process providers and provider-based IPC between an app's processes never reached the main process (web pages could not read the login state).
- `ActivityStack`/`BActivityManagerService`/`BProcessManagerService`: when a clone process dies its activity records are dropped (`onProcessDied`), and finished records are no longer matched by component. Stale records made a restarted clone "deliver" its main-activity launch to the dead process, so returning to a clone the system had killed ended on the launcher instead of reopening it.
- Added focus tracking: `activityPaused` is hooked next to `activityResumed`, the server remembers the resumed clone activity, and `BlackBoxCore.getFocusedClone()` returns it as `userId:packageName` (null when no clone is in the foreground).
- `IOCore.enableRedirect`: the shared media folders (`DCIM`, `Pictures`, `Movies`, `Music`, `Download`, `Documents`) are no longer redirected into the clone's private external storage; previously only `Pictures` was exempt, so files listed by the media store could not be opened and photo pickers showed blank thumbnails.
- `IOCore.redirectPath`: a path inside an exempt folder is returned unchanged. It used to return the matched prefix (the folder itself), so the exemption never worked for files.
- `BActivityManagerService.onProcessDied` takes `synchronized (userSpace.mStack)` around `ActivityStack.onProcessDied` (was racing `startActivityLocked` iteration).
- `ActivityStack.onActivityCreated` clears `finished` and removes the record from the task before re-adding, so a stub activity recreated after a process death is matched again and not listed twice.
- `BProcessManagerService`/`ProcessRecord`: a stale record dropped in `startProcessLocked` is fully cleaned up there (proc dir, notifications, activity stack, outside `mProcessLock`) and marked via `ProcessRecord.markDead()`; the late `onProcessDie` is then a no-op. `onProcessDie` also skips `removeProc` when a live record owns the same bpid and skips notification deletion when a live replacement of the same clone process exists.
- `BProcessManagerService.isAliveL` no longer uses `pingBinder()` (false negatives for frozen cached apps): alive if the binder is alive or `record.pid` is still a running stub process of our uid.
- `BActivityThread` keeps the unfiltered provider list (`getAllProviders()`); `FileProviderHandler.convertFile` uses it so secondary processes can resolve main-process FileProvider URIs. Installed providers remain filtered per process.
- `BlackBoxCore.isEngineAlive()` is a pure probe of the cached package-manager binder in `mServices` (no restart, no sleep); false when nothing is cached.
- `InnerReceiverDelegate.finishSkipped` falls back to `ActivityManagerNative.getDefault()` when `ActivityManager.getService()` is missing (API 21-25).
- `IOCore.redirectPath(String)` normalises absolute paths textually (`normalizePath`: `.`, `..`, duplicate slashes) before the exempt and redirect lookups, so `/sdcard/DCIM/../Foo` no longer escapes redirection.
- Clone switching: bringing a clone to the front uses a fade-and-grow transition (`res/anim/bb_clone_enter`, `bb_clone_exit`, `utils/SwitchAnimation`) for `moveTaskToFront`, new-task launches and the splash; `BlackBoxCore.startActivity` skips the splash activity when the clone is already running.
- `IActivityManagerProxy.GetContentProvider`: Google authorities (`com.google.android.gms*`, `com.android.vending*`, `com.google.android.gsf*`) are resolved against the calling virtual user first (`resolveContentProvider`) and served by that user's own copy of the package when it has one; they pass through to the phone's real Google services only when the user has none (same order as `startService`/`bindService`). Users without virtual Google services behave exactly as before.
- `GmsCore.installGApps`/`uninstallGApps`: fail with a clear error when the phone has no Google Play services (it used to report success after installing nothing) and when GMS is still missing after the loop; roll back only the packages that call installed (it used to uninstall every Google package of the user); stop every package of the user before and after, so apps re-bind to the right Google services; per-user only (data of those packages in that user is removed by the existing `RemoveUserExecutor`, other users keep the shared copy).
- `BAccountManagerService`: `BUserAccounts.userId` was never set (always 0), so authenticator binds (`_B_|_UserId`), `checkKeyIntent` and the token cache of every virtual user addressed user 0. `getUserAccounts`/`loadAccounts` now set it from the map key.
- `BAccountManagerService.loadAuthenticatorCache(pkg)` cleared the whole authenticator cache and kept only `pkg`'s authenticators, so installing any app dropped the Google (`com.google`) authenticator; it now replaces only that package's entries.
- `BAccountManagerService.onPackageUninstalled`: uninstalling `com.google.android.gms` from a user removes that user's `com.google*` accounts and their cached tokens (other users untouched).
- Added `res/values-zh/strings.xml` with Chinese text for the daemon notification.
- `IPackageManagerProxy.getPackageInfo`: `com.android.vending` is answered with the clone number's own Play Store when installed, else the phone's real one, and only then the signature-less placeholder. The unconditional placeholder made Google apps report "device not supported" because the Play Store did not look Google-signed.
- `IActivityManagerProxy.BroadcastIntent`: the target user argument is forced to the host user. A clone's `sendBroadcastAsUser(USER_ALL)` (used by Google Play services) crashed it with a SecurityException.
- `BAccountManagerService`: the authenticator bind goes through the engine's own service path (`BActivityManagerService.bindService`) instead of a plain `Context.bindService`. In the server process binds are not redirected, so adding an account bound the phone's real authenticator and failed with a SecurityException.
- `IActivityManagerProxy`: hooked `checkPermissionForDevice` (the Android 14+ form of `checkPermission`) with the same answers as the existing `checkPermission` hook.
- `IUserManagerProxy`: `getApplicationRestrictionsForUser` returns an empty bundle instead of reaching the system, which refused it for a clone and broke adding a Google account.
- `cpp/Utils/VirtualSpoof.cpp`: the inline (Dobby) hook on libc `__system_property_get` is no longer installed by a library constructor in every process; `set_spoof_props` installs it once, the first time a non-empty override table is set (a device profile that changes properties). Patched libc made 360 Jiagu-packed apps (for example 唱吧) skip unpacking and call `System.exit(1)` from `com.stub.StubApp`, so their clones restarted in a loop on a black screen (seen on a moto g 5G 2024, Android 15). Clones with such a device profile still get the hook, and Jiagu apps will still fail in them.
